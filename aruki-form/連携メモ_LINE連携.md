# 歩き方診断 × 自前LINEツール 連携メモ

自前のLINE連携ツール（別システム）と歩き方診断フォームを繋ぐための取り決め。
LINE送信そのものは別システム側の実装。本フォーム側は「誰の提出か」を確実に
記録するところまでを担当する。

## 1. 紐付けの仕組み（uid）

- フォームの公開URL（特典サイトと同じ仕組み・こちらを配布する）:
  **https://bikyaku-selfdesign.web.app/aruki-form/**
  （GitHub Pages版 https://yokutaro0607-create.github.io/bikyaku-lp/aruki-form/ も併存。どちらからでも動作）
- LINEツールからフォームURLを配信する際、**受信者ごとに `?uid=<LINEのuserId>` を付けて配る**。
  例: `https://bikyaku-selfdesign.web.app/aruki-form/?uid=U1234567890abcdef...`
- フォームはこの `uid` を自動で読み取り、提出データと一緒にGASへ送る（受講者は何も入力しない）。
- `uid` 無しでフォームが開かれた場合のみ、「LINEのお名前（表示名）」欄が表示され必須になる
  （手動照合のフォールバック）。

## 2. 提出一覧スプレッドシートの列（受け渡し契約）

Googleドライブ「歩き方診断_フォーム提出」フォルダ内の「歩き方診断_提出一覧」。

| 列 | 見出し | 書き込む側 |
|---|---|---|
| A | 提出日時 | GAS（提出時） |
| B | 名前 | GAS |
| C | メール | GAS |
| D〜G | ①不調面／②見た目面／③歩き方／④変わりたい姿 | GAS |
| H | フォルダURL（動画・写真・回答.txtの保存先） | GAS |
| I | LINE_UID（配信URLのuid。無ければ空） | GAS |
| J | LINE名（uid無し提出時のみ入力される表示名） | GAS |
| K | 診断結果（例「（3）固定ブレーキタイプ」） | 診断ツール（syncShindan経由で自動記入） |
| L | 動画リンク（本人フォルダにコピー済みの配信動画のDrive URL） | 診断ツール（同上） |
| M | 承認（プルダウン。**人が「承認」にしたら送信してよい**） | 人（チェック担当） |
| N | 送付済み（送信日時を記入。空=未送信） | LINEツール側 |

- 各提出者フォルダの `回答.txt` にも `LINE_UID:` / `LINE名:` の行が入る。

## 3. AI診断＝タイプ判定 — 実装済み（過去の運用を踏襲）

無料診断は過去の運用と同じく**タイプ①〜④を判定し、タイプ別の既製動画を送る**方式。
一人ひとり録画はしない。AIは判定部分を自動化する（`C:\Users\yokut\walk-diagnosis`・Gemini）。

- `③_無料診断を作る.bat`（diagnose_form.py）が提出フォルダを走査し、
  未診断の人の動画・靴裏をGeminiで分析 → **各提出者フォルダに `診断判定.txt` を出力**
  （①〜④の判定＋配信動画名＋根拠。人がチェックしてから配信）。
- 既製動画の場所:
  `マイドライブ\【共有】脳バグから始める美脚セルフデザイン用_ファイル\歩き方診断《診断結果》\配信用\歩き方診断（1）〜（4）.mp4`
- タイプ対応: （1）置き去りブレーキ=仙骨 ／（2）前のめりブレーキ=距骨 ／
  （3）固定ブレーキ=肋骨 ／（4）横揺れブレーキ=股関節
- 診断ロジックは `knowledge.md`（2026-07のyumico監修で精度強化済み。主タイプ一致83%）。

## 4. LINEツール側の送信フロー（ブス足診断と同じ「承認→送信」方式）

1. 提出一覧スプシを読み、「**M列=承認 かつ N列（送付済み）が空**」の行を抽出
2. I列の LINE_UID 宛に、L列の動画（本人フォルダにコピー済みの「歩き方診断_○○さん.mp4」）を送信
   （uidが空の行はJ列のLINE名で手動対応）
3. 送信できたら N列 に送信日時を記入（二重送信防止）

## 5. 補足

- GAS側の受け口（doPost）の合言葉は `index.html` の `FORM_KEY` と同じ。
- 既存スプシに I〜L 列が無い場合、次の提出時に自動でヘッダーが追記される（`ensureColumns_`）。
