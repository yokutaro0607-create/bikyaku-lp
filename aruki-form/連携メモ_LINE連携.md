# 歩き方診断 × 自前LINEツール 連携メモ

自前のLINE連携ツール（別システム）と歩き方診断フォームを繋ぐための取り決め。
LINE送信そのものは別システム側の実装。本フォーム側は「誰の提出か」を確実に
記録するところまでを担当する。

## 1. 紐付けの仕組み（uid）

- LINEツールからフォームURLを配信する際、**受信者ごとに `?uid=<LINEのuserId>` を付けて配る**。
  例: `https://<配信URL>/aruki-form/?uid=U1234567890abcdef...`
- フォームはこの `uid` を自動で読み取り、提出データと一緒にGASへ送る（受講者は何も入力しない）。
- `uid` 無しでフォームが開かれた場合のみ、「LINEのお名前（表示名）」欄が表示され必須になる
  （手動照合のフォールバック）。

## 2. 提出一覧スプレッドシートの列（受け渡し契約）

Googleドライブ「歩き方診断_フォーム提出」フォルダ内の「歩き方診断_提出一覧」。

| 列 | 見出し | 書き込む側 |
|---|---|---|
| A | 提出日時 | GAS（提出時） |
| B | 名前 | GAS |
| C | メール | GAS |
| D〜G | ①不調面／②見た目面／③歩き方／④変わりたい姿 | GAS |
| H | フォルダURL（動画・写真・回答.txtの保存先） | GAS |
| I | LINE_UID（配信URLのuid。無ければ空） | GAS |
| J | LINE名（uid無し提出時のみ入力される表示名） | GAS |
| K | 診断結果（診断文。AI/人が記入） | 診断側（今後実装） |
| L | 結果送信済み（送信日時などを記入。空=未送信） | LINEツール側 |

- 各提出者フォルダの `回答.txt` にも `LINE_UID:` / `LINE名:` の行が入る。

## 3. AI診断（無料診断）の生成 — 実装済み

診断は既存ツール `C:\Users\yokut\walk-diagnosis`（ローカルPC・Gemini）で行う。

- `③_無料診断を作る.bat`（diagnose_form.py）が提出フォルダを走査し、
  未診断の人の動画・靴裏をGeminiで分析 → **各提出者フォルダに `診断結果.txt` を出力**。
- `診断結果.txt` の冒頭コメントに LINE_UID / LINE名 が入る。本文がそのままLINE送信用の下書き。
- **AI下書き＋人の確認**運用：送信前に必ず内容をチェック・修正する。
- 診断ロジックは `knowledge.md`（2026-07のyumico監修で精度強化済み。主タイプ一致83%）。

## 4. LINEツール側の送信フロー（案・別途検討）

1. 提出者フォルダの `診断結果.txt`（人の確認済みのもの）を取得
   ※スプシK列への転記は未実装。必要ならGASに同期関数を追加するか、ツールがフォルダを直接読む
2. LINE_UID 宛に診断結果をpush送信（uidが空の場合はLINE名で手動対応）
3. 送信できたら スプシL列（または `_送信済.txt`）に記録（二重送信防止）

## 5. 補足

- GAS側の受け口（doPost）の合言葉は `index.html` の `FORM_KEY` と同じ。
- 既存スプシに I〜L 列が無い場合、次の提出時に自動でヘッダーが追記される（`ensureColumns_`）。
